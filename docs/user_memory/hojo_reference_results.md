# Hojo MemoryEngine: Published Reference Results

These self-run results were generated by the Hojo AI team using self-hosted
Hojo MemoryEngine services. They belong to **Published Reference Results**.
Benchmark-specific models, prompts, retrieval budgets and ingestion settings
are documented below; these runs have not been reproduced through
OmniMemEval's shared baseline pipeline.

## Summary

| Benchmark | Evaluated scope | Overall metric | Score | Completion |
| --- | --- | --- | ---: | --- |
| [LoCoMo](#locomo) | 1,540-question non-adversarial subset, 10 conversations | LLM-as-a-judge accuracy | **88.12%** | 1,540/1,540 evaluated successfully |
| [LongMemEval-S](#longmemeval-s) | Full 500-question split | LLM-as-a-judge accuracy | **80.60%** | All 500 questions completed successfully |
| [BEAM 100K](#beam-100k) | 20 conversations, 400 questions | Mean Nugget Score | **69.58%** | 400/400 evaluated successfully |
| [HaluMem-Medium](#halumem-medium) | Full 3,467-question split, 20 users | QA accuracy | **77.33%** | 3,467/3,467 evaluated successfully |
| [PersonaMem v2](#personamem-v2) | 200 personas, 5,000 questions | Multiple-choice accuracy | **35.14%** | 5,000/5,000 evaluated successfully |
| [BEAM 10M](#beam-10m) | Not included in this submission | Mean Nugget Score | — | Supporting materials pending |

Each included result has zero final execution failures, exclusions or skipped
questions within its stated scope. Binary accuracies are the mean of one valid
binary judgment per question; BEAM is the mean of unrounded per-question
scores. Category percentages are rounded only for display. Overall scores are
question-weighted, rather than the unweighted mean of displayed category scores.

Model and scoring settings are documented in the individual benchmark sections
and the accompanying machine-readable configurations.

## Public supporting materials

The [artifact directory](./hojo_artifacts/) contains a score record for every
evaluated question, including its category, status and dataset index or question
hash. BEAM records also retain numerical rubric-item scores where applicable.
These files permit checking record counts, unique IDs and recomputing all
included aggregates without model calls. The verifier also checks contiguous
dataset indexes for LongMemEval-S and PersonaMem v2. It does not load the
official datasets or independently verify every question hash against them;
record-count checks are not a complete dataset coverage audit.
They omit credentials, service user IDs, questions,
conversation datasets, answers and retrieval contexts.

- [Machine-readable configurations, aggregates and source hashes](./hojo_artifacts/summary.json)
- [Record integrity and aggregation verifier](./hojo_artifacts/verify_results.py)
- [Artifact preparation script](./hojo_artifacts/prepare_results.py)

## LoCoMo

The table entry covers the **1,540-question non-adversarial subset**. Its score
is **88.12%**. Each question has one retained answer and one judge result;
adversarial questions are outside this table entry's denominator.

| Category | Questions | Judge accuracy |
| --- | ---: | ---: |
| Single-Hop | 841 | 92.98% |
| Multi-Hop | 282 | 81.91% |
| Temporal | 321 | 85.36% |
| Open-Domain | 96 | 72.92% |
| **Overall** | **1,540** | **88.12%** |

Run: `hojo_locomo_full_max10k_20261012a`. Semantic retrieval used `top_k=20`,
`candidate_limit=200`, `min_score=0`, and `max_tokens=10000`. Strict-fair mode
disabled action-query expansion, multi-pass retrieval and assistant-response
query expansion. The report records 1,540 answer calls and 1,540 judge calls.
The retained report states a mean answer-stage prompt/input count of
**9,360.3** tokens. The supporting token totals are not included, so the
comparison table leaves `Context Tokens` as `-`. A dataset revision/hash and
corrected-answer-key flag were not retained; no answer-key correction is claimed.

[Per-question scores](./hojo_artifacts/locomo.jsonl).

## LongMemEval-S

The full **500-question LongMemEval-S evaluation has been completed
successfully**. Overall LLM-as-a-judge accuracy is **80.60%**. Aggregation is
the arithmetic mean of one binary judgment for each of the 500 dataset indexes;
no answer-run or judge-run averaging is used.

| Category | Questions | Judge accuracy |
| --- | ---: | ---: |
| Single-Session User | 70 | 98.57% |
| Single-Session Assistant | 56 | 78.57% |
| Single-Session Preference | 30 | 83.33% |
| Temporal Reasoning | 133 | 78.95% |
| Multi-Session | 133 | 68.42% |
| Knowledge Update | 78 | 88.46% |
| **Overall** | **500** | **80.60%** |

Run: `hojo_lme_full_gpt_20261022a`, self-hosted canal deployment. Dataset:
`longmemeval_s_cleaned.json.gz`, decompressed-data SHA-256
`d6f21ea9d60a0d56f34a05b609c79c88a451d2ae03597821ea3d5a9678c3a442`.
Ingestion used `direct_message_claims_v2` with assistant messages included.
Retrieval used `top_k=20`, `candidate_limit=200`, `min_score=0.5`, and
`max_tokens=1500`, with `assistant_recall_profile=bounded_second_pass_v1`.
Answer and judge temperature were 0. The judge accepts a binary
`CORRECT`/`WRONG` label. Context-token statistics are not reported.

[Per-question scores](./hojo_artifacts/longmemeval_s.jsonl) cover all dataset
indexes 0 through 499.

## BEAM 100K

This entry uses the complete run
`hojo_beam100k_grounded_full_p6_20261015a`: **20 conversations, 400 questions**,
mean Nugget Score **69.58%**. The configuration was fixed across the full run.

| Dimension | Questions | Mean score |
| --- | ---: | ---: |
| Abstention | 40 | 82.50% |
| Contradiction Resolution | 40 | 69.06% |
| Event Ordering | 40 | 35.92% |
| Information Extraction | 40 | 83.44% |
| Instruction Following | 40 | 80.00% |
| Knowledge Update | 40 | 58.75% |
| Multi-Session Reasoning | 40 | 70.45% |
| Preference Following | 40 | 85.63% |
| Summarization | 40 | 71.31% |
| Temporal Reasoning | 40 | 58.75% |
| **Overall** | **400** | **69.58%** |

For rubric-scored questions, each atomic item receives 1.0, 0.5 or 0.0 and
the question score is the mean of its item scores. Event-ordering questions
use the runner's Kendall tau-b scoring branch. The overall score is the mean
of all 400 unrounded question scores.

Dataset SHA-256:
`5f4e24cc25769a84da86b77ffa77f314bf8c833a868016bef7ef2346198b3ed9`.
The run used `direct_message_claims_v3`, 6 workers, `top_k=20`,
`candidate_limit=200`, `min_score=0.5`, and `max_tokens=1500`. Ordering and
summary retrieval allowed `candidate_limit=400`, `min_score=0.35`, and a
broader context budget of 6,000 tokens. Profiles were
`prompt_profile=omnimemeval_beam_evidence_v3`,
`retrieval_profile=multi_pass_session_coverage_v1`,
`context_profile=code_compact_v1`, and `evidence_profile=user_grounded_v1`.
These prompts and retrieval passes are custom reference-run settings.
Context-token statistics are not reported. No answer-key correction is claimed.

[Per-question scores and numerical rubric scores](./hojo_artifacts/beam100k.jsonl).

two attempts to obtain a parseable label; valid judgments are not averaged.

`486fbc130a5c8781a2af27ffa508a1d7855245137aa449c193ac4d29c45634e7`.

## Runtime and source provenance

Final question execution completed successfully, but the retained files do not establish that every
claim was indexed or later backfilled. These scores describe the observed
deployments, including that limitation.

The [artifact notes](./hojo_artifacts/README.md) distinguish recorded run
identifiers, dataset hashes and source snapshots from deployment revisions
that were not captured. No missing deployment commit or corrected answer-key
status is inferred from a later checkout.

pipeline will be submitted separately. This documentation submission does not
claim inclusion in the main reproduced-results table.
